## Objective

Give Group Password Reset the same visual family as Site Inspector: a branded header, readable navy text, orange section bars, white cards, clear status summaries, and consistent spacing. Adapt these patterns to a password-reset workflow, where the selected scope and consequences must remain clear.

Starting baseline: Group Password Reset 3.4.3. Current local and Zendogs review build: 3.5.0. The previous interface used a versioned heading, a lead paragraph, a reset form card, a “What happens” card, progress, and latest results. The implemented interface follows the layout below.

## Approved and implemented page layout

1. **Branded header:** mascot, small “THE HACK REPAIR GUY'S” eyebrow, “Group Password Reset” heading, subdued version, and a short task-focused introduction.
2. **Choose accounts:** orange section bar and white card containing the existing scope selector and excluded usernames.
3. **Notifications and confirmation:** clearly labeled email choice, contextual email warning, existing required acknowledgement, then the reset button.
4. **Progress:** existing live status, progress bar, and processed counts presented as a Site Inspector-style information panel.
5. **Latest results:** summary tiles followed by the existing per-user table and any details-availability note.
6. **How it works:** concise supporting guidance below the task; a disclosure is optional if its contents remain accessible without JavaScript.

Keep the main workflow in one column. Avoid adding navigation tabs or a sticky action bar in the initial visual update. The primary action should follow its scope, notification choice, warning, and acknowledgement in reading order.

## Behavior that must survive the redesign

- Explicit scope selection; no preselected reset scope.
- Administrator scope excludes the current account as implemented today.
- Excluded usernames, required confirmation, and existing notification defaults.
- Password-reset and email outcomes remain distinct; do not describe mail acceptance as confirmed delivery.
- Capability and nonce checks, job ownership, batching, and stored results behavior.
- JavaScript and no-JavaScript submission paths.
- No password reset triggered by loading the page, changing a selection, or opening a disclosure.

An account-preview feature, changed email defaults, new confirmation steps, or reset-engine changes require their own implementation scope. They are not prerequisites for this visual upgrade.

## Administrator summary notifications (3.5.0)

After a completed reset, use **Notify administrators** to select current administrator accounts, add an optional note, preview the summary, and choose **Email to administrators**. Recipients are not selected automatically. This manual notification works independently of the affected-user email setting, including reset-only mode.

The server keeps the initiating administrator’s latest summary for 15 minutes. A newer completed run replaces it. The email includes site URL, completion time, scope, counts, exclusions count, and notification mode; it excludes passwords, reset links, usernames, and individual email addresses. A personal note is included exactly as sanitized text, so avoid adding sensitive details.

Sending requires administrator permission and a valid nonce. Recipients are checked against current administrator accounts (up to 100 shown); repeat sends are throttled for one minute. Each recipient receives a separate email. Feedback distinguishes acceptance for sending from failure and does not guarantee delivery. Both JavaScript and regular form submission are supported.

Validation on October 18, 2026: shared PHPCS passed for all 10 first-party PHP files; notification tests passed 12 checks, and updater-message regressions passed. JavaScript/PHP syntax and diff whitespace checks passed. Zendogs browser simulation verified summary availability, recipient selection, optional note, preview, send feedback, and button recovery; a 390px viewport had no horizontal overflow.
